## Summary

Broker ingest now matches ESP32-Multi-Pzem-Main **v1.2.0**: window kWh is derived on the server from `energy_first` / `energy_last` / calibration. Hardware reset **wipes** the register series (no window-sum, no P×Δt). CD verifies migration `005` is in the VPS package.

## Included commits

- e13662f feat: derive window kWh on broker for firmware v1.2.0

## Features

- Independent wrap/reset classification with calibrated wrap (`9999.99 * scale + offset`)
- Derived `accumulated_energy_kwh` on ingest; leftover v1.1.0 payload keys ignored
- PLN T0→T1 match uses register delta / wrap; reset → `reset_wipe` (optional suffix is not the bill)
- `/pln-match` shows post-reset suffix as informational only

## Fixes

- CD package check now requires `shared/energy_derive.py` and `005` SQL so the VPS cannot deploy without them

## Breaking changes

- Reset periods no longer produce a T0→T1 `phase_kwh` from summed windows. `total_kwh` is omitted until all three phases have a complete register series.

## Database / migrations

- Applied on dashboard and mqtt-listener startup: `004_pln_bill_match.sql` then `005_firmware_v12_derive.sql`
- Adds nullable `pzem_data.energy_scale` and `pzem_data.energy_offset`
- Existing `accumulated_energy_kwh` / `energy_method` columns are reused as **broker-derived** values (`delta` \| `wrap` \| `reset` \| `untrusted`)
